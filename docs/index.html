Banh-Mi-Guard

The Sandwich Pattern Regression Guard for AI-Assisted Development

📦 okrath/banh-mi-guard v0.15.0 Apache-2.0 👤 Author: @okrath
⭐ Star on GitHub

Dual-Gate Impact Analysis & Regression Guard for AI-Assisted Development.
A safety harness around AI coding agents (Claude Code, Cursor, Windsurf, Aider, omp): scope and diff checks, static rules and project invariants at no token cost, then an LLM review, before a change is accepted.

1. Overview & Vision

Coding agents are fast, but they can be careless: they accidentally delete keyboard shortcuts, drop responsive CSS classes, leak API tokens, or make out-of-scope modifications across untouched files.

guard enforces a deterministic Sandwich Pattern around every task:

Before code is touched (Pre-Task): guard records the declared scope and a baseline snapshot, detects the repository domain, extracts existing baseline contracts, and locks the project invariants.

After code is written (Post-Task): guard measures the exact diff blast radius and scans its static rulebook, on request (guard post --full) Alibaba Open Code Review (OCR) reviews the changes with your LLM (with --full, a high or critical finding, OCR not running or a review OCR did not complete blocks approval; lower findings are reported, and an OCR status of skipped is reported without blocking. A plain guard post reports OCR as "not run", which never blocks), the project build/test command runs, the invariant checks verify the locked rules, and your configured LLM issues the final authoritative verdict (APPROVED or REVISE).

3. 2D Quality Matrix: Platform Domains × Quality Pillars

Guard looks at a change across 5 Platform Domains (frontend, backend, fullstack, infra, mobile) and 7 Cross-Cutting Quality Pillars. In each cell, a rule ID is a deterministic check on the diff, run on every guard post at no token cost; what follows the ·, or a cell without an ID, is what the LLM review is asked to look at (concerns like resource leaks, null dereferences, blocking async calls, dead code, and over-engineering are checked by the LLM review in every language). Most rules read the lines a change adds and skip docs, tests, comments and lines over 2,000 characters (the LLM review still sees them); for those line rules, a line marked guard-allow <RULE>: <reason> in a comment stays in the report as a LOW note. quality-pillars.md lists every rule.

Focused Deep-Dives (--focus)

By default, all quality pillars are audited at 100% rigor. When investigating specific defects, use the --focus flag to direct the LLM gate's analytical scrutiny: 

# Scrutinize KISS, YAGNI, over-engineering & dependency bloat:
guard review --focus simplicity

# Scrutinize dead code, zombie blocks & orphan files:
guard review --focus dead-code
# Ask the LLM review to look at memory handling (listeners, unclosed handles):
guard review --focus memory

# Scrutinize security vulnerabilities (SQLi, XSS, secrets):
guard review --focus security

# Scrutinize performance (blocking I/O, heavy operations):
guard review --focus performance

# Scrutinize ergonomics and responsive UX:
guard review --focus ux

4. Installation Guide (Cross-Platform)

Works natively on Windows, Linux, and macOS:

# Recommended: Install globally from PyPI via pipx (Linux/macOS)
pipx install banh-mi-guard

# Or with standard pip (Windows / Linux / macOS)
pip install banh-mi-guard

# Or the newest main branch straight from GitHub (can be ahead of the last release)
pip install git+https://github.com/okrath/banh-mi-guard.git

# Install globally (hooks + agent directives), no model download needed:
guard install

# Verify installation health
guard doctor

5. LLM Setup Wizard & Auto-Sync

Run the interactive step-by-step wizard to configure your preferred LLM provider. The settings are written into the Alibaba OCR CLI as its custom provider guard, so the optional OCR review that guard post --full adds uses the same LLM: 

guard config llm
  • OpenAI / OpenAI-Compatible: OpenAI, DeepSeek, Ollama (http://localhost:11434/v1), OpenRouter, or Local Gateways (http://127.0.0.1:8090/v1).
  • Anthropic: Claude API (any current Claude model).

Test your connection with an instant sub-second verification ping:

guard config test

Choose who writes commit messages for approved work: auto lets the agent write them, ask makes it ask you for each one. guard doctor always shows the choice as "Commit messages" (guard install lists it only while it is still unset), and an approved post report ends with a Commit line that tells the agent what to do.

guard config commit auto

6. Install: Global or Workspace

Two ways to install, neither needs a per-repository step:

# Global (whole machine): Git hooks for every repository + guard directives in the global
# instruction file of each installed agent (Claude Code, Codex, Gemini CLI, opencode)
guard install

# Workspace (one folder only): directives in that folder's CLAUDE.md / AGENT.md
# + Git hooks in its repository or every repository below it
guard install --workspace path/to/workspace

# Remove what install added
guard uninstall [--workspace path/to/workspace]

The agent reads the directives and runs guard pre before editing; the first guard run inside a repository sets it up, and the Git hook checks every commit. Agents without a global instruction file (Cursor, omp) get the directives through a workspace install.

🧾 No diff in your repository: inside a repository guard writes only in .git and the Git-excluded .guard/ folder (local invariants, sessions, reports). Repository files (agent docs, hooks kept in the tree such as .husky/, guard.invariants.json) are only read; guard doctor tells you what to change. Where guard is asked to write agent docs, it appends a marked block and keeps your content (.guard.bak backup).

After an upgrade, guard update self refreshes what guard installed and prints a setup check; guard doctor shows the same check at any time.

7. CLI Command Reference

Command Description Common Flags
guard install Install globally (hooks + agent directives) or for one folder --workspace <dir>
guard pre "<prompt>" Run Pre-Task Guard: scope, baseline, contracts & locked invariants --scope <path>, --allow-dirty, --force
guard post Run Post-Task Guard: diff audit, rules, build, invariants, LLM final gate --focus <area>, --hook, --full
guard run "<prompt>" -- <cmd> Execute Sandwich Pattern: pre ➔ command ➔ post --scope, --allow-dirty, --force
guard invariants init / check Create the local invariants file / evaluate every rule on the current code --shared
guard reset Close the current session (archived to .guard/history/) —
guard finding <id> Record a deferral or a rejection of a review finding; the next review sees the reason --defer "<why>", --reject "<evidence>"
guard accept Your decision on a task that used its review rounds: approve as reviewed, or allow three more rounds interactive terminal only
guard review Perform on-demand LLM Code Review on current git diff --focus <area>
guard config llm Launch interactive LLM configuration wizard (an API, or your own claude / codex CLI) --local
guard agent add / list / test / fix / remove Put guard on an agent's own hooks (Claude Code, Codex, Cursor, Grok Build, Gemini CLI, Antigravity, ZCode, omp, pi, opencode, or any other agent guard can set up) test --report, fix --note
guard config test Send instant token-free ping test to configured LLM —
guard config sync Write the LLM settings into Alibaba OCR (custom provider guard) —
guard config commit Choose who writes commit messages: the agent (auto) or you (ask) auto | ask
guard hook refresh Refresh what guard installed earlier to the current version —
guard update Safely upgrade Alibaba OCR respecting 3-day quarantine --check, --force, self
guard doctor Check system environment health and supply-chain security --no-updates, -q <days> (also shows the setup check)

8. Supply-Chain Security & Quarantine Policy

To protect development environments against zero-day npm supply-chain backdoors, Guard enforces a 3-Day Quarantine Cooling Period on Alibaba OCR releases:

  • New releases published < 3 days ago are placed on QUARANTINE HOLD to allow security researchers time to detect malicious insertions.
  • Releases published ≥ 3 days ago are marked SAFE UPDATE.
# Check update status safely without installing:
guard update --check

# Safely upgrade (automatically halts if release is under quarantine):
guard update

# Bypass quarantine hold explicitly if verified:
guard update --force
